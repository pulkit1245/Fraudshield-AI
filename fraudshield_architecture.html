1. High-Level Architecture
FraudShield AI is a layered, queue-driven system. An analyst uploads a suspicious APK through the React dashboard; the FastAPI backend persists the file, computes its SHA-256, and enqueues a static-analysis job. Static extraction (Androguard/Apktool/JADX) and dynamic sandboxing (Frida-instrumented emulator) run as parallel Celery workers behind RabbitMQ, so a slow sandbox run never blocks the faster static path. Every extracted string that will reach the LLM first passes through a dedicated adversarial-sanitization layer — the model producing the final verdict is never the first system to see untrusted, attacker-authored content. Findings are aggregated, scored by an ensemble (rules + XGBoost classifier + Claude API reasoning), and rendered as a plain-English report an L1 analyst can act on without reading decompiled code.

Authentication Flow
Analysts register/login via /api/v1/auth. The backend issues a short-lived JWT access token (15 min) plus a rotating refresh token (7 days), both signed with an HS256 secret stored in environment variables. The React app stores the access token in memory (not localStorage) and the refresh token in an HttpOnly cookie. Every protected FastAPI route depends on an get_current_user dependency that validates the JWT and role (analyst / lead / admin).
Security
Uploaded APKs are treated as hostile input end-to-end: stored in an isolated object-storage bucket with no execute permissions, hashed on arrival, and never executed outside the sandboxed emulator with zero real network egress. Role-based access control gates the verdict-override and escalate endpoints to lead/admin roles. All LLM prompts pass through the sanitization layer, and any detected prompt-injection attempt is logged to audit_logs and surfaced in the final report.
Caching, Error Handling & Logging
Redis caches dashboard aggregate stats (60s TTL) and VirusTotal hash lookups (24h TTL) to reduce external-API cost. All FastAPI routes return a standard error envelope ({"error": {"code","message","request_id"}}) via a shared exception-handler middleware. Structured JSON logs (via structlog) are shipped to stdout and collected by the hosting platform's log stream; each request is tagged with a request_id for tracing across the static → dynamic → LLM → scoring pipeline.
Monitoring & Deployment
The backend, worker fleet, frontend, and Postgres/RabbitMQ are deployed as separate services (see §13 Deployment) with independent scaling. A /health endpoint on the API and a Celery flower dashboard on the worker fleet give at-a-glance liveness; Railway/Render built-in metrics cover CPU/memory, with Sentry wired into both FastAPI and React for error tracking.

5. API Architecture
Auth
POST/api/v1/auth/register
Registers a new analyst account under a bank/NBFC org.
Request: {email, password, org_name} · Response: {id, email, role} · Validation: email format, password ≥ 10 chars · Auth: none · Errors: 409 email exists, 422 validation
POST/api/v1/auth/login
Authenticates and returns an access + refresh token pair.
Request: {email, password} · Response: {access_token, refresh_token, expires_in} · Auth: none · Errors: 401 invalid credentials
POST/api/v1/auth/refresh
Rotates a valid refresh token for a new access token.
Request: {refresh_token} · Response: {access_token, expires_in} · Errors: 401 expired/invalid
GET/api/v1/auth/me
Returns the authenticated analyst's profile.
Auth: Bearer JWT · Errors: 401 unauthenticated
Submissions
POST/api/v1/submissions
Uploads a raw APK (multipart/form-data), computes SHA-256, stores it, and enqueues static + dynamic analysis jobs.
Request: multipart file (max 200MB, .apk only) · Response: {id, status:"queued", sha256_hash} · Validation: MIME/magic-byte check for valid APK/ZIP signature · Auth: Bearer JWT · Errors: 413 too large, 415 invalid file type
GET/api/v1/submissions
Paginated queue listing with filters (status, severity, date range).
Response: {items:[...], total, page} · Auth: Bearer JWT
GET/api/v1/submissions/{id}
Full submission detail: static + dynamic findings, ML scores, LLM report, verdict.
Auth: Bearer JWT · Errors: 404 not found
GET/api/v1/submissions/{id}/status
Lightweight polling endpoint for pipeline stage (used by the frontend queue view every 3s until completed).
Response: {status, progress_pct} · Auth: Bearer JWT
DELETE/api/v1/submissions/{id}
Soft-deletes a submission (compliance retention rules apply; raw APK purged after 90 days regardless).
Auth: Bearer JWT, role lead/admin · Errors: 403 insufficient role
Analysis Pipeline (internal + read)
GET/api/v1/submissions/{id}/static-findings
Returns permissions, certificate info, API-call graph, obfuscation score.
Auth: Bearer JWT
GET/api/v1/submissions/{id}/dynamic-findings
Returns sandbox behaviour: SMS access, accessibility abuse, overlay detection, captured network calls.
Auth: Bearer JWT
GET/api/v1/submissions/{id}/ml-score
Returns classifier score, novelty score, and top SHAP feature contributions.
Auth: Bearer JWT
GET/api/v1/submissions/{id}/report
Returns the full rendered LLM report (summary, TTP mapping, sanitization flags) for export/print.
Auth: Bearer JWT
Verdicts
GET/api/v1/submissions/{id}/verdict
Returns the calibrated 0–100 risk score, severity band, and recommended action.
Auth: Bearer JWT
PATCH/api/v1/submissions/{id}/verdict/override
Allows a lead analyst to override the model's score with a human judgement, logged to audit_logs.
Request: {override_score, reason} · Auth: Bearer JWT, role lead/admin · Errors: 403 insufficient role
POST/api/v1/submissions/{id}/verdict/escalate
Marks a submission for CERT-In/NPCI escalation and generates a structured IOC record.
Auth: Bearer JWT, role lead/admin
Clusters, Chat & VirusTotal
GET/api/v1/clusters
Lists campaign clusters with member counts, used to build the Sankey/heatmap views.
Auth: Bearer JWT
POST/api/v1/submissions/{id}/chat
"Chat with the APK" — analyst asks a natural-language question about the sample; answered against the sanitized findings + retrieved TTP context, never against raw untrusted strings directly.
Request: {message} · Response: {reply, sources} · Auth: Bearer JWT · Errors: 429 rate-limited (Claude API tier cap)
GET/api/v1/submissions/{id}/virustotal
Cross-checks the SHA-256 against VirusTotal; cached 24h in Redis to conserve quota.
Auth: Bearer JWT
GET/api/v1/dashboard/stats
Aggregate counts by severity band, queue depth, and average triage time, cached 60s.
Auth: Bearer JWT

User Flow

Commit Convention

Merge Strategy & PR Rules
Squash-merge into main. Every PR requires: CI green (lint + test), 1 peer review, no direct schema changes to shared/schemas/ without a message in the team channel. Member D merges integration PRs; feature PRs are reviewed cross-member (A↔B, C↔D) to spread pipeline knowledge.
Conflict Resolution & Versioning
Schema conflicts resolved by treating shared/schemas/ as source of truth — whoever changes it updates the API_CONTRACTS.md in the same PR. Semantic versioning tags on submission: v1.0.0-submission. Rollback via git revert on main, never force-push.

12. Testing Plan
Unit Testing
Pytest for every service and repository (hashing, sanitization pattern matching, scoring ensemble math, clustering similarity). Vitest + React Testing Library for component logic (queue filters, polling hook, chat state).

Pytest + httpx against a test Postgres instance covering the full submission→static→dynamic→scoring→verdict chain with a seeded fixture APK, run in CI on every PR touching backend/.

Contract tests validating every response against the JSON schemas in shared/schemas/, run as part of CI so a frontend/backend field mismatch fails the build instead of surfacing at demo time.

Component tests for ReportViewer, QueueTable, ChatPanel; a Playwright smoke test for the critical path (login → upload → view report) run against a staging deploy before each checkpoint.

Locust load test simulating 50 concurrent submissions to confirm the Celery worker queue absorbs bursts without the API blocking, validating the horizontal-scaling claim in §2.7 Scalability.

Manual adversarial test set of prompt-injection strings run through the sanitization layer (target: 100% flag rate on the known set); JWT tampering and expired-token rejection tests; role-escalation attempt tests on the override/escalate endpoints.
Acceptance Testing
Walkthrough against the 2.3 Impact Metrics: sub-5-minute first-pass triage on a seeded sample, ≥80% repacked-variant clustering accuracy on the labelled test set, before final sign-off.
